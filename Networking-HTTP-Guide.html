IP addresses, subnets and CIDR Basic

An IPv4 address is 32 bits written as four decimal bytes (192.168.10.37). A CIDR prefix (/24) says how many leading bits are the network part; the rest identify the host. Hosts in the same subnet talk directly; to reach other subnets they send packets to the default gateway (a router).

RangeMeaning

  • NAT (network address translation): a router rewrites private source addresses to its public address so many hosts share one public IP. Inbound traffic needs port forwarding or a load balancer.
  • DHCP hands out IP, mask, gateway and DNS to devices automatically.
  • ARP maps an IP on the local network to a MAC address.
  • IPv6 uses 128-bit addresses (2001:db8::1), removes the need for NAT and is gradually replacing IPv4. Dual-stack runs both.
  • Ports: 16-bit numbers identify the service (80 HTTP, 443 HTTPS, 22 SSH, 53 DNS, 25/587 SMTP, 1433 SQL Server, 5432 PostgreSQL, 3306 MySQL, 6379 Redis, 3389 RDP). A socket is IP + port + protocol.

TCP and UDP Basic

TCPUDP
ConnectionConnection-oriented (handshake)Connectionless
ReliabilityAcknowledgements, retransmission, ordering, no duplicatesNone: packets may be lost, duplicated or reordered
Flow / congestion controlYes (window, slow start)No
Overhead / latencyHigher (setup + head-of-line blocking)Low
Used byHTTP/1.1, HTTP/2, SMTP, SSH, databasesDNS queries, video/voice, games, QUIC (HTTP/3), DHCP
  • The handshake costs one round trip (RTT) before any data. Reusing connections (keep-alive, pooling, HTTP/2) avoids repeating it.
  • Slow start: new connections begin with a small congestion window; large transfers speed up gradually, another reason to reuse connections.
  • Port exhaustion / TIME_WAIT: creating a new connection for every call (e.g. new HttpClient() per request in .NET) exhausts ephemeral ports. Use IHttpClientFactory or a shared HttpClient.

DNS: the internet's phone book Basic

DNS translates names (api.shop.com) into IP addresses. It is a distributed, hierarchical, cached database; usually UDP port 53 (TCP for large answers; DoH/DoT encrypt it).

TLS and HTTPS Intermediate

TLS (Transport Layer Security) gives HTTPS three guarantees: confidentiality (encryption), integrity (tamper detection) and authentication (the server is who the certificate says). It uses asymmetric cryptography to agree on a key and the faster symmetric encryption for the data.

ConceptExplanation
Certificate (X.509)Binds a public key to a domain, signed by a Certificate Authority (CA). Contains subject/SAN, validity dates, issuer.
Chain of trustServer cert → intermediate CA → root CA that is preinstalled in the OS/browser trust store. Servers must send the intermediates.
SNIThe client names the host in the handshake so one IP can serve many certificates.
Forward secrecyEphemeral (ECDHE) keys mean a stolen private key cannot decrypt past traffic.
HSTSStrict-Transport-Security header makes browsers use HTTPS only for that domain.
mTLSThe client also presents a certificate (service-to-service and zero-trust).
TLS terminationThe load balancer/CDN decrypts at the edge; traffic behind it may be re-encrypted (end-to-end) or plain inside a trusted network.
Let's Encrypt / ACMEFree automated certificates (90-day) renewed automatically.
openssl s_client -connect shop.com:443 -servername shop.com -showcerts   # inspect the handshake and chain
curl -vI https://shop.com 2>&1 | grep -E "SSL|subject|expire|issuer"
dotnet dev-certs https --trust                                           # local ASP.NET Core dev certificate
Common TLS errors"Certificate expired" (renewal failed), "hostname mismatch" (name not in SAN), "unable to get local issuer certificate" (missing intermediate or untrusted private CA), clock skew, TLS version/cipher mismatch with old clients. Never "fix" it with ServerCertificateCustomValidationCallback = (...) => true in production.

Part 4 — Caching and cross-origin rules

HTTP caching: Cache-Control, ETag and validation Intermediate

The fastest request is one never sent. Caches live in the browser, CDNs and proxies. The server controls them with response headers; a cached copy is fresh (use it with no network) until it goes stale, then it can be revalidated cheaply.

DirectiveMeaning
max-age=NFresh for N seconds in any cache (s-maxage for shared caches only)
no-cacheMay store, but must revalidate with the origin before each use
no-storeDo not store at all (sensitive data)
public / privateShared caches/CDNs allowed / browser only (user-specific data)
immutableNever changes during its lifetime: skip revalidation (hashed filenames)
stale-while-revalidate=NServe stale instantly while refreshing in the background
Vary: Accept-EncodingThe response differs by this request header; caches key on it
// Hashed static assets: cache for a year; HTML/API: always validate
app.UseStaticFiles(new StaticFileOptions {
    OnPrepareResponse = ctx => ctx.Context.Response.Headers.CacheControl =
        ctx.File.Name.Contains('.') && ctx.Context.Request.Path.StartsWithSegments("/assets")
            ? "public,max-age=31536000,immutable" : "no-cache"
});
app.UseResponseCompression();      // br/gzip   |   [ResponseCache(Duration = 60)] / output caching for endpoints

Same-origin policy and CORS Intermediate

The browser's same-origin policy stops a page from reading responses from a different origin (scheme + host + port). CORS (Cross-Origin Resource Sharing) is how a server opts in to sharing. The restriction is enforced by the browser; Postman and curl ignore it, which is why "it works in Postman".

PageRequest toSame origin?
https://app.shop.comhttps://app.shop.com/apiYes
https://app.shop.comhttp://app.shop.com/apiNo (scheme)
https://app.shop.comhttps://api.shop.comNo (host)
http://localhost:4200http://localhost:5000No (port)
builder.Services.AddCors(o => o.AddPolicy("spa", p => p
    .WithOrigins("http://localhost:4200", "https://app.shop.com")   // exact origins, never "*" with credentials
    .WithMethods("GET", "POST", "PUT", "DELETE")
    .WithHeaders("Authorization", "Content-Type")
    .AllowCredentials()
    .SetPreflightMaxAge(TimeSpan.FromMinutes(10))));

app.UseCors("spa");          // before UseAuthentication / UseAuthorization
CORS is not security for your APIIt only governs which web pages may read responses in a browser. Attackers use curl. You still need authentication, authorisation and CSRF protection (SameSite cookies, anti-forgery tokens) on the server.

Part 7 — Interview preparation

Self-test quiz Practice

Ten questions. Pick an answer and read the explanation.

Networking and HTTP interview questions Prep

Filter by topic, expand a question and try to answer it aloud first.

What happens when you type a URL in the browser? stack

Browser checks caches/HSTS → DNS resolves the name → TCP handshake → TLS handshake → HTTP request (with cookies) → load balancer/proxy routes to the app → the app queries data and responds → browser parses HTML and fetches sub-resources over the same connection, then renders.

TCP vs UDP? stack

TCP: reliable, ordered, connection-oriented with flow and congestion control. UDP: connectionless, no guarantees, low latency. DNS, streaming, gaming and QUIC use UDP; HTTP/1.1 and 2 use TCP.

What is a subnet mask / CIDR and how do you split 10.0.0.0/16 into subnets? stack

The prefix length marks network bits. Adding bits splits it: /16 into /24 gives 256 subnets of 256 addresses each (e.g. 10.0.1.0/24, 10.0.2.0/24). Plan non-overlapping ranges and remember cloud providers reserve 5 addresses per subnet.

How does DNS work and what is TTL? stack

A recursive resolver walks root → TLD → authoritative servers and caches the answer for its TTL. Lower the TTL ahead of a migration; propagation delay is just cached answers expiring.

What is NAT and why is it used? stack

Network Address Translation lets many private hosts share one public IP by rewriting addresses/ports at the router, conserving IPv4 space. It also hides internal addressing and blocks unsolicited inbound traffic by default.

PUT vs POST vs PATCH? http

POST creates or triggers processing (not idempotent). PUT replaces a resource at a known URL (idempotent). PATCH partially updates (may not be idempotent).

401 vs 403 and 404 vs 410? http

401: not authenticated. 403: authenticated but not authorised. 404: not found (or deliberately hidden); 410: permanently gone.

HTTP/1.1 vs HTTP/2 vs HTTP/3? http

1.1: text, one request at a time per connection. 2: binary, multiplexed streams and header compression on one TCP connection. 3: the same model over QUIC/UDP, fixing TCP head-of-line blocking, faster setup and connection migration.

What is statelessness and how do you keep state? http

Each request has all the information needed to process it; the server keeps no per-client memory between requests, which allows horizontal scaling. State travels in cookies, tokens, or is stored in a shared store (Redis/database) keyed by a session id.

What is the difference between cookies, localStorage and sessionStorage? http

Cookies are sent automatically with each matching request, can be HttpOnly/Secure/SameSite, ~4 KB. localStorage persists, ~5-10 MB, JavaScript-only, never sent automatically. sessionStorage is per tab and cleared on close.

Explain CORS and a preflight request. web

Browsers block cross-origin reads unless the server sends permission headers. For non-simple requests (custom headers, JSON content-type, PUT/DELETE) the browser first sends OPTIONS to ask. The server must answer with allowed origin, methods and headers. Fix it on the server, and note it is not an API security mechanism.

How does HTTP caching work (ETag, Cache-Control)? web

Cache-Control says how long a response is fresh; once stale the client revalidates with If-None-Match/If-Modified-Since and gets a tiny 304 if unchanged. Use long max-age + immutable for hashed assets, and no-cache + ETag for HTML and API data.

How do you make a website load faster? web

Reduce round trips and bytes: CDN, HTTP/2-3, keep-alive, compression, caching headers, minify and code-split, optimise images, preload critical resources, lazy-load, and reduce server time (indexes, caching). Measure with DevTools, Lighthouse and real-user metrics (Core Web Vitals).

How does HTTPS/TLS work at a high level? sec

The client validates the server's certificate chain and hostname, both sides agree on session keys using an ephemeral key exchange, then data is encrypted symmetrically with integrity checks. Forward secrecy means recorded traffic cannot be decrypted later.

XSS vs CSRF and their defences? sec

XSS runs attacker script in your page (defend with encoding, CSP, HttpOnly). CSRF makes a victim's browser send an authenticated request from another site (defend with SameSite cookies, anti-forgery tokens). Bearer tokens in headers avoid CSRF but make XSS more damaging if stored in localStorage.

What is SSRF and how do you prevent it? sec

Server-Side Request Forgery: user-supplied URLs make the server call internal resources such as the cloud metadata endpoint. Allow-list destinations, resolve and block private/link-local ranges, disable redirects, and use IMDSv2 / least-privilege roles.

Users report 502s intermittently. How do you investigate? ops

Check which hop returns 502 (CDN, LB, gateway, app), upstream health probes and logs for crashes/restarts, timeouts vs upstream latency, connection limits and keep-alive mismatches between proxy and app, recent deployments and scaling events. Correlate with request ids and metrics.

Layer 4 vs Layer 7 load balancing? ops

L4 forwards TCP/UDP connections by IP and port: fast, protocol-agnostic. L7 understands HTTP: routes by path/host/header, terminates TLS, does cookies, rewrites and WAF, at slightly higher cost.

What is the difference between liveness and readiness probes? ops

Liveness answers "should this process be restarted?"; readiness answers "should this instance receive traffic right now?" (dependencies warmed up, DB reachable). Keep liveness simple to avoid restart loops.
