Part 1 — Core ideas

What React is and why it exists Basic

React is a JavaScript library for building user interfaces from reusable components. It is declarative: you describe the UI for a given state and React updates the DOM efficiently. It is a library, not a full framework: routing, data fetching and forms come from the ecosystem (or a framework built on React such as Next.js).

IdeaMeaning
ComponentA function that takes props and returns UI (JSX)
DeclarativeYou write what it should look like, not the step-by-step DOM mutations
One-way data flowData flows parent → child through props; children notify parents through callbacks
Virtual DOM & reconciliationReact compares the new element tree with the previous one and applies only the minimal real-DOM changes
ImmutabilityState is never changed in place; you give React a new value so it can see that something changed
Composition over inheritanceBuild complex UIs by nesting components and passing children/props

Where React runs

  • Client-side SPA (Vite + React Router): the browser downloads JS and renders.
  • Server rendering / SSG (Next.js, Remix/React Router framework mode): HTML comes from the server, then hydrates.
  • React Native: same component model for iOS/Android.
  • Server Components (React 19 frameworks): components that run only on the server and send no JS for themselves.

JSX Basic

JSX is syntax sugar for React.createElement / the JSX runtime calls. It looks like HTML but it is JavaScript: the build tool (Babel/SWC/esbuild) turns it into function calls.

type GreetingProps = { name: string; unread?: number };

export function Greeting({ name, unread = 0 }: GreetingProps) {
  const isVip = name === 'Asha';
  return (
    <section className="card" style={{ padding: 16 }}>       {/* className, camelCase style object */}
      <h2>Hello, {name.toUpperCase()}!</h2>                {/* any JS expression in { } */}
      {unread > 0 && <span>{unread} new messages</span>}   {/* conditional render */}
      {isVip ? <b>VIP</b> : <i>member</i>}
      <label htmlFor="q">Search</label><input id="q" />       {/* htmlFor, self-closing tags */}
    </section>
  );
}
JSX ruleDetail
One rootReturn a single parent, or a Fragment <>...</> (no extra DOM node)
Attributes are camelCaseclassName, htmlFor, onClick, tabIndex
Expressions, not statementsUse ternary and &&; put if/for above the return
Auto-escapingInterpolated strings are escaped, which helps prevent XSS. dangerouslySetInnerHTML bypasses it: sanitise first
0 && ... pitfall{count && <List/>} renders "0" when count is 0. Use count > 0 && ...
Components start with a capital<Greeting/> is a component; <div> is a DOM tag

Components, props and children Basic

A component is a function. Props are its (read-only) inputs. A component must be pure during render: same props and state in, same JSX out, no side effects.

import type { ReactNode } from 'react';

type CardProps = {
  title: string;
  footer?: ReactNode;
  children: ReactNode;            // whatever is nested between the tags
  onClose?: () => void;           // callback prop: child tells parent something happened
};

export function Card({ title, footer, children, onClose }: CardProps) {
  return (
    <article className="card">
      <header><h3>{title}</h3>{onClose && <button onClick={onClose}>x</button>}</header>
      {children}
      {footer && <footer>{footer}</footer>}
    </article>
  );
}

// usage
<Card title="Order #12" footer={<small>Paid</small>} onClose={() => setOpen(false)}>
  <OrderLines id={12} />
</Card>

Props rules

  • Read-only: never modify props
  • Pass functions to send events up
  • Spread ({...rest}) to forward attributes
  • In React 19, ref is an ordinary prop for function components

Composition patterns

  • children for layout wrappers
  • Slots via props (header=<...>)
  • Render props (rare now)
  • Custom hooks instead of HOCs for reuse

Rendering lists, keys, events and conditionals Basic

type User = { id: number; name: string; active: boolean };

export function UserList({ users, onSelect }: { users: User[]; onSelect: (id: number) => void }) {
  if (users.length === 0) return <p>No users yet.</p>;                    // early return
  return (
    <ul>
      {users.filter(u => u.active).map(u => (
        <li key={u.id} onClick={() => onSelect(u.id)}>{u.name}</li>   {/* key = stable id */}
      ))}
    </ul>
  );
}
TopicRules
KeysUnique among siblings, stable across renders, from your data (id). Not Math.random(), and avoid the array index when the list can reorder or change. Keys are not passed as a prop.
EventsPass a function, do not call it: onClick={handle}, not onClick={handle()}. Handlers receive a synthetic event (e.preventDefault(), e.stopPropagation()).
ConditionalsEarly return, ternary, &&; extract a component when the branches get big.
FormsControlled inputs: value comes from state, onChange updates it. Uncontrolled: read via ref or FormData.
Part 2 — State, hooks and effects

useState and state as a snapshot Basic

useState gives a component memory. State belongs to a component instance at a position in the tree. Calling the setter schedules a re-render; the new value is visible on the next render, not on the next line.

import { useState } from 'react';

export function Counter() {
  const [count, setCount] = useState(0);
  const [user, setUser] = useState({ name: 'Asha', tags: ['new'] });

  function addThree() {
    setCount(count + 1); setCount(count + 1); setCount(count + 1);       // adds 1 (stale snapshot)
    setCount(c => c + 1); setCount(c => c + 1); setCount(c => c + 1);   // adds 3 (functional updates)
  }
  function rename(n: string) {
    setUser({ ...user, name: n });                                        // new object: never mutate user.name = n
  }
  function addTag(t: string) {
    setUser(u => ({ ...u, tags: [...u.tags, t] }));                       // new array too
  }
  return <button onClick={() => setCount(c => c + 1)}>Clicked {count} times</button>;
}
RuleWhy
Treat state as immutableReact uses Object.is to decide if state changed; mutating in place keeps the same reference, so nothing re-renders
Use the updater form when the new value depends on the oldAvoids stale values and works when updates are batched
Updates are batchedSeveral setters in one event cause one render (React 18+ batches everywhere, including promises and timeouts)
Lazy initial valueuseState(() => expensive()) runs only once
Derive, do not duplicateCompute fullName or a filtered list during render instead of storing it in a second state variable
Lift state upWhen two components need the same state, move it to the closest common parent and pass it down
Immutable update cheat sheet
// object:  { ...obj, key: value }
// nested:  { ...s, address: { ...s.address, city: 'Pune' } }
// array add:     [...arr, item]          remove: arr.filter(x => x.id !== id)
// array replace: arr.map(x => x.id === id ? { ...x, done: true } : x)
// insert at i:   [...arr.slice(0, i), item, ...arr.slice(i)]
// deep or heavy updates: use Immer (produce) or useImmerReducer

useEffect: synchronising with the outside world Intermediate

An effect runs after React has painted and is for syncing with something outside React: network subscriptions, timers, browser APIs, non-React widgets. It re-runs when a value in its dependency array changed, and its cleanup runs before the next run and on unmount.

import { useEffect, useState } from 'react';

function OnlineBadge({ userId }: { userId: number }) {
  const [online, setOnline] = useState(false);

  useEffect(() => {
    const ws = new WebSocket(`wss://api.shop.com/presence/${userId}`);
    ws.onmessage = e => setOnline(JSON.parse(e.data).online);
    return () => ws.close();                 // cleanup: runs before re-run and on unmount
  }, [userId]);                               // re-sync when userId changes

  return <span>{online ? 'Online' : 'Offline'}</span>;
}

function useDocumentTitle(title: string) {
  useEffect(() => { document.title = title; }, [title]);
}

function Clock() {
  const [now, setNow] = useState(() => new Date());
  useEffect(() => {
    const id = setInterval(() => setNow(new Date()), 1000);
    return () => clearInterval(id);
  }, []);                                     // [] = set up once on mount
  return <time>{now.toLocaleTimeString()}</time>;
}
You need to...Do this (no effect needed)
Compute a value from props/stateCalculate it during render (use useMemo only if it is measurably slow)
Respond to a user actionPut the logic in the event handler
Reset state when a prop changesGive the component a different key
Fetch dataPrefer a data library (TanStack Query / SWR) or framework loaders; a raw effect needs cancellation and race handling
Adjust state based on other stateDerive it, or update both in one handler

Common bugsMissing dependencies (stale values, use the react-hooks/exhaustive-deps lint rule); an object/function created each render in the deps (infinite loop); setting state inside an effect with no deps; forgetting cleanup so listeners and timers leak.

import { useReducer, useRef, useMemo, useCallback } from 'react';

type Action = { type: 'add'; text: string } | { type: 'toggle'; id: number } | { type: 'clear' };
type Todo = { id: number; text: string; done: boolean };

function reducer(state: Todo[], a: Action): Todo[] {
  switch (a.type) {
    case 'add':    return [...state, { id: Date.now(), text: a.text, done: false }];
    case 'toggle': return state.map(t => t.id === a.id ? { ...t, done: !t.done } : t);
    case 'clear':  return [];
  }
}

export function Todos() {
  const [todos, dispatch] = useReducer(reducer, []);
  const inputRef = useRef<HTMLInputElement>(null);
  const remaining = useMemo(() => todos.filter(t => !t.done).length, [todos]);
  const add = useCallback(() => {
    const v = inputRef.current!.value.trim();
    if (v) { dispatch({ type: 'add', text: v }); inputRef.current!.value = ''; inputRef.current!.focus(); }
  }, []);
  return (<>
    <input ref={inputRef} /> <button onClick={add}>Add</button> <span>{remaining} left</span>
    <ul>{todos.map(t => <li key={t.id} onClick={() => dispatch({ type: 'toggle', id: t.id })}>{t.done ? '✓ ' : ''}{t.text}</li>)}</ul>
  </>);
}
Rules of HooksCall hooks only at the top level of a component or custom hook (never in loops, conditions or nested functions) and only from React functions. React identifies hooks by call order, so the order must be identical every render.

Custom hooks: reusing stateful logic Intermediate

A custom hook is a function whose name starts with use and that calls other hooks. It shares logic, not state: each caller gets its own state.

import { useEffect, useState } from 'react';

export function useDebounce<T>(value: T, ms = 300): T {
  const [v, setV] = useState(value);
  useEffect(() => { const id = setTimeout(() => setV(value), ms); return () => clearTimeout(id); }, [value, ms]);
  return v;
}

export function useLocalStorage<T>(key: string, initial: T) {
  const [value, setValue] = useState<T>(() => {
    try { const raw = localStorage.getItem(key); return raw ? (JSON.parse(raw) as T) : initial; } catch { return initial; }
  });
  useEffect(() => { localStorage.setItem(key, JSON.stringify(value)); }, [key, value]);
  return [value, setValue] as const;
}

// usage
const [theme, setTheme] = useLocalStorage('theme', 'light');
const q = useDebounce(search, 400);          // call the API with q, not search
Part 3 — Sharing state

Context: sharing values without prop drilling Intermediate

Context lets a provider make a value available to any descendant. It is ideal for slowly changing, app-wide values: theme, locale, current user, feature flags.

import { createContext, useContext, useMemo, useState, type ReactNode } from 'react';

type Auth = { user: string | null; login: (u: string) => void; logout: () => void };
const AuthContext = createContext<Auth | null>(null);

export function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<string | null>(null);
  const value = useMemo(() => ({ user, login: setUser, logout: () => setUser(null) }), [user]);   // stable identity
  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
}

export function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth must be used inside <AuthProvider>');
  return ctx;
}
Context is not a state manager for fast-changing dataEvery consumer re-renders when the provider value changes. Split contexts (state vs dispatch), keep values stable with useMemo, or use a store with selectors for frequently changing data.

Part 4 — Routing, data and forms

Client-side routing with React Router Intermediate

A SPA has one HTML page; the router maps URLs to components using the History API (no full page reload). It also handles nested layouts, dynamic params, redirects, and lazy loading.

import { createBrowserRouter, RouterProvider, Outlet, Link, NavLink, useParams, useNavigate,
         useSearchParams, Navigate } from 'react-router-dom';
import { lazy, Suspense } from 'react';

const Admin = lazy(() => import('./pages/Admin'));            // code-split route

function Layout() {
  return (<>
    <nav><NavLink to="/">Home</NavLink> <NavLink to="/products">Products</NavLink></nav>
    <Outlet />                                                {/* child route renders here */}
  </>);
}

function ProductPage() {
  const { id } = useParams();                                 // /products/42 -> "42"
  const [sp, setSp] = useSearchParams();                      // ?tab=reviews
  const navigate = useNavigate();
  return <button onClick={() => navigate('/products')}>Back (id {id}, tab {sp.get('tab')})</button>;
}

function RequireAuth({ children }: { children: JSX.Element }) {
  const { user } = useAuth();
  return user ? children : <Navigate to="/login" replace />;       // route guard
}

const router = createBrowserRouter([
  { path: '/', element: <Layout />, errorElement: <p>Something went wrong</p>, children: [
      { index: true, element: <Home /> },
      { path: 'products', element: <ProductList /> },
      { path: 'products/:id', element: <ProductPage />,
        loader: ({ params }) => fetch(`/api/products/${params.id}`) },       // data loading before render
      { path: 'admin', element: <RequireAuth><Suspense fallback="Loading..."><Admin /></Suspense></RequireAuth> },
      { path: '*', element: <p>404</p> },
  ]},
]);

export default function App() { return <RouterProvider router={router} />; }

Data fetching and server state Intermediate

Fetching in effects works but you must handle loading, errors, caching, retries, de-duplication, race conditions and refetching yourself. TanStack Query does it declaratively.

import { QueryClient, QueryClientProvider, useQuery, useMutation, useQueryClient } from '@tanstack/react-query';

const qc = new QueryClient({ defaultOptions: { queries: { staleTime: 30_000, retry: 2 } } });
// <QueryClientProvider client={qc}><App /></QueryClientProvider>

const getProducts = async (q: string): Promise<Product[]> => {
  const r = await fetch(`/api/products?q=${encodeURIComponent(q)}`);
  if (!r.ok) throw new Error(`HTTP ${r.status}`);
  return r.json();
};

export function Products({ q }: { q: string }) {
  const { data, isPending, isError, error, refetch } = useQuery({ queryKey: ['products', q], queryFn: () => getProducts(q) });
  const queryClient = useQueryClient();
  const add = useMutation({
    mutationFn: (p: NewProduct) => fetch('/api/products', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(p) }),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ['products'] }),     // refetch the list
  });

  if (isPending) return <p>Loading...</p>;
  if (isError) return <p>{error.message} <button onClick={() => refetch()}>Retry</button></p>;
  return <ul>{data.map(p => <li key={p.id}>{p.name}</li>)}</ul>;
}
What the cache gives youInstant UI from cached data while a background refetch runs (stale-while-revalidate), request de-duplication, retries with back-off, pagination/infinite scroll helpers, optimistic updates, and refetch on focus/reconnect. The queryKey identifies the data; include every variable the query depends on.
Token storagePrefer HttpOnly, Secure, SameSite cookies for session tokens. A JWT in localStorage is readable by any XSS payload. See the AngularJS guide's storage section: the same trade-offs apply to any SPA.

Forms and validation Intermediate

import { useForm } from 'react-hook-form';
import { z } from 'zod';
import { zodResolver } from '@hookform/resolvers/zod';

const schema = z.object({
  email: z.string().email('Enter a valid email'),
  password: z.string().min(8, 'At least 8 characters'),
});
type Form = z.infer<typeof schema>;

export function LoginForm({ onLogin }: { onLogin: (f: Form) => Promise<void> }) {
  const { register, handleSubmit, formState: { errors, isSubmitting } } = useForm<Form>({ resolver: zodResolver(schema) });
  return (
    <form onSubmit={handleSubmit(onLogin)} noValidate>
      <label>Email <input type="email" {...register('email')} /></label>
      {errors.email && <p role="alert">{errors.email.message}</p>}
      <label>Password <input type="password" {...register('password')} /></label>
      {errors.password && <p role="alert">{errors.password.message}</p>}
      <button disabled={isSubmitting}>Sign in</button>
    </form>
  );
}
  • Controlled inputs re-render on every keystroke; React Hook Form uses uncontrolled inputs for speed.
  • One schema (Zod/Yup) can validate both client and server input and infer the TypeScript type.
  • Always validate again on the server: client validation is for user experience, not security.
  • Accessibility: label every input, link errors with aria-describedby, announce them with role="alert".
Part 5 — Performance, testing and build

Performance Advanced

React is fast by default. A component re-renders when its state changes, its parent re-renders, or a context it reads changes. Re-rendering is cheap unless the work is large; measure first with the React DevTools Profiler.

TechniqueUse when
Move state down / lift content upOnly a small part needs the changing state; pass the rest as children
React.memo(Component)A child re-renders with identical props and its render is expensive. Needs stable props (useMemo/useCallback)
useMemo / useCallbackExpensive calculations; stable references for memoised children or effect deps
Virtualised listsThousands of rows: render only visible ones (react-window, TanStack Virtual)
Code splittinglazy() + Suspense per route; dynamic import() for heavy libraries
useTransition / useDeferredValueKeep typing responsive while a heavy list updates
Stable keys, avoid inline object props to memoised childrenPreserve DOM and state, avoid needless work
Bundle hygieneAnalyse bundle size (vite-bundle-visualizer), tree-shake, import only what you use, compress, cache with hashed filenames
React CompilerNewer build step that auto-memoises; reduces manual useMemo/useCallback
const Row = memo(function Row({ item, onSelect }: { item: Item; onSelect: (id: number) => void }) {
  return <li onClick={() => onSelect(item.id)}>{item.name}</li>;

  const [selected, setSelected] = useState(0);
  const onSelect = useCallback((id: number) => setSelected(id), []);   // same function every render -> Row can skip

Premature memoisationWrapping everything in memo/useMemo adds code and comparison cost and can hide bugs. Profile, find the slow commit, then fix that one.

React interview questions Prep

Filter by topic, expand a question and try to answer it aloud first.

What is the virtual DOM and reconciliation? core

React builds a lightweight tree of elements for each render, diffs it against the previous one (keys identify items; different element types replace subtrees) and applies only the necessary changes to the real DOM. It is an implementation detail that makes declarative UI efficient, not a guarantee of being faster than hand-tuned DOM code.

Props vs state? core

Props are inputs from the parent, read-only. State is owned by the component, changes over time and triggers a re-render. A child's props are often the parent's state.

Controlled vs uncontrolled components? core

Controlled: React state is the single source of truth (value + onChange). Uncontrolled: the DOM holds the value and you read it with a ref or FormData. Controlled enables live validation; uncontrolled is simpler and faster for big forms.

Function vs class components? core

Function components with hooks are the standard. Class components (lifecycle methods, this.setState) still work and are needed for error boundaries, which have no hook equivalent (use react-error-boundary).

What are error boundaries? core

Components that catch render errors in their subtree and show a fallback. They do not catch event-handler, async or server errors.

What are Fragments and Portals? core

Fragments group children without an extra DOM node. Portals render children into a different DOM node (modals, tooltips) while keeping React tree behaviour such as context and event bubbling.

Explain useEffect and its cleanup. hooks

It runs after render to synchronise with an external system, re-running when dependencies change. The returned cleanup runs before the next effect and on unmount to remove listeners, timers and subscriptions. Don't use it to derive state or handle events.

useMemo vs useCallback vs React.memo? hooks

useMemo caches a computed value; useCallback caches a function (shorthand for useMemo returning a function); React.memo skips re-rendering a component if props are shallow-equal. They are performance tools used after measuring.

What are the Rules of Hooks and why do they exist? hooks

Only call hooks at the top level and from React functions. React associates state with hooks by call order, so conditional or looped calls would shift that mapping and corrupt state.

How is useRef different from useState? hooks

Both persist across renders, but changing ref.current does not trigger a re-render. Use refs for DOM nodes, timer ids and values not shown in the UI; use state for anything that affects rendering.

Why does my effect run twice in development? hooks

StrictMode intentionally mounts, unmounts and remounts to reveal effects without proper cleanup. It happens only in development and is a prompt to make the effect idempotent with a cleanup.

How do you avoid prop drilling? state

Composition (pass children/elements), context for app-wide values, or a store (Zustand/Redux) for shared client state. Keep server data in a query cache rather than copying it into global state.

Redux vs Context vs Zustand? state

Context is a delivery mechanism, good for low-frequency values. Zustand is a small store with selector-based subscriptions. Redux Toolkit adds structure, devtools and middleware for large teams. Choose the simplest that fits.

How do you handle API data, loading and errors? state

Use TanStack Query (or a framework loader): query keys, loading/error states, caching with staleTime, retries and invalidation after mutations. With plain effects use AbortController and handle race conditions.

How would you implement authentication in a React SPA? state

Prefer OIDC/OAuth2 with PKCE (e.g. MSAL, Auth0) or a backend-for-frontend that sets HttpOnly cookies. Keep auth state in context, add route guards, attach tokens in an API client, handle 401 with refresh or redirect, and enforce permissions on the server.

How do you diagnose and fix a slow React screen? perf

Profile with React DevTools (which components render and why), check for unnecessary state at a high level, large lists (virtualise), expensive computations (memo), huge bundles (code split), and network waterfalls (parallel requests/prefetch). Fix the measured bottleneck.

Why does a component re-render? perf

Its state changed, its parent re-rendered (children re-render by default even with the same props), or a context it consumes changed. Memoisation and moving state down are the usual remedies.

What is code splitting? perf

Loading JavaScript on demand. With lazy(() => import('./Page')) and Suspense, each route or heavy feature becomes its own chunk, shrinking the initial bundle.

CSR vs SSR vs SSG, and where does Next.js fit? ecosystem

CSR renders in the browser (simple, poorer SEO/first paint). SSR renders HTML per request; SSG at build time; both hydrate on the client. Next.js provides routing, data loading, SSR/SSG/ISR and React Server Components on top of React.

How do you test React components? ecosystem

Vitest/Jest with React Testing Library, querying by role and text and simulating users with user-event, MSW to mock the network, Playwright for end-to-end. Test behaviour, not implementation.

React vs Angular? ecosystem

React is a focused library: you choose routing, state and forms yourself (flexible, minimal). Angular is an opinionated framework with DI, RxJS, router, forms and CLI built in (consistent structure, steeper curve). Both are valid; team size, conventions and existing code decide.
