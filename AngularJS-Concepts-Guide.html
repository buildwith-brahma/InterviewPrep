Part 1 — AngularJS fundamentals

What is AngularJS? Basic

AngularJS is a client-side JavaScript framework (Google, first released 2010) for building single-page applications (SPAs). You extend HTML with new attributes (directives), bind your page to JavaScript data (two-way data binding) and organise logic into modules, controllers and services wired together by dependency injection.

Why did it exist?In 2010, building rich pages meant hand-written jQuery: finding elements, copying values to and from the DOM, and keeping both in sync. AngularJS made the data the single source of truth: change the model and the view updates; type in the view and the model updates. That removed huge amounts of glue code and gave teams structure, testability and a standard way to build SPAs.

Key characteristics

  • MVC / MVVM style – Model (plain JS objects on $scope), View (HTML template), Controller / ViewModel (functions that prepare the model).
  • Declarative templates – HTML plus {{ expressions }} and directives such as ng-repeat.
  • Two-way data binding – implemented by dirty checking in the digest cycle.
  • Dependency injection built in – services are requested by name and supplied by the injector.
  • Directives – teach HTML new tricks; reusable UI building blocks.
  • Testability – DI plus angular-mocks make unit tests straightforward.

Modules and bootstrapping Basic

A module is a named container for the parts of your app: controllers, services, directives, filters, configuration. Modules declare their dependencies on other modules, so AngularJS can load everything in the right order.

Why modules?They stop everything living in the global scope, make features self-contained (a users module, an orders module), and let tests load only what they need.
// SETTER: the second argument (the dependency array) CREATES the module
angular.module('shop', ['ngRoute', 'ngCookies', 'shop.products']);

// GETTER: no second argument -> retrieve the existing module
angular.module('shop')
  .config(function ($routeProvider) { /* runs once, before the app starts */ })
  .run(function ($rootScope) { /* runs once, after injector is created */ });

// Feature module
angular.module('shop.products', [])
  .controller('ProductListCtrl', ProductListCtrl)
  .factory('ProductService', ProductService);
Classic bugangular.module('shop', []) called a second time re-creates the module and silently wipes everything registered earlier. Use the one-argument getter form everywhere except the very first declaration.

Expressions and data binding Basic

An AngularJS expression is a small JavaScript-like snippet written in {{ }} or in a directive attribute. It is evaluated against the current scope, never against window.

<p>{{ 1 + 2 }}</p>                          <!-- 3 -->
<p>{{ user.name | uppercase }}</p>             <!-- property + filter -->
<p>{{ items.length > 0 ? 'has items' : 'empty' }}</p>
<p>{{ undefinedVar.deep.prop }}</p>             <!-- renders empty, no TypeError (forgiving) -->

The dot rule (prototypal scope inheritance)

Child scopes (created by ng-repeat, ng-if, ng-controller...) prototypally inherit from the parent. Binding a primitive in a child writes a new property on the child and hides the parent’s value.

<!-- BAD: ng-if creates a child scope, typing creates child.name; parent.name never changes -->
<div ng-if="show"><input ng-model="name"></div>
<p>{{ name }}</p>

<!-- GOOD: bind to a property of an object ("always have a dot in your ng-model") -->
<div ng-if="show"><input ng-model="form.name"></div>
<p>{{ form.name }}</p>

<!-- BEST: controllerAs makes every binding "vm.something" -->
<div ng-controller="FormCtrl as vm"><input ng-model="vm.name"></div>

Scope and the digest cycle Mid

$scope is the object that glues a controller to its view. $rootScope is the parent of all scopes; child scopes form a tree that mirrors the DOM structure of controllers and directives.

How can AngularJS know that a value changed?It does not observe properties. Instead, every {{ }}, ng-model or $watch registers a watcher (a getter function + a listener). After any event that AngularJS knows about, it runs the digest cycle: it loops over every watcher, compares the current value with the last remembered value (dirty checking), and calls the listener if different. Because a listener may change other data, it repeats until a full pass finds nothing dirty (maximum 10 passes by default).

Watching manually

// Reference watch (default): fires when the value / reference changes
var stop = $scope.$watch('vm.query', function (newVal, oldVal) {
  if (newVal !== oldVal) vm.search(newVal);       // first call has newVal === oldVal
});

$scope.$watch('vm.items', fn, true);              // deep watch (angular.equals): expensive
$scope.$watchCollection('vm.items', fn);          // shallow: add/remove/reorder only
$scope.$on('$destroy', stop);                     // deregister (scopes do this for you on destroy)
Why is AngularJS slow with thousands of bindings?

Every digest runs every watcher at least twice (once to find changes, once to confirm stability). 2,000+ watchers on a page can make each keystroke visibly slow. The remedies are listed in the performance chapter: one-time bindings, track by, pagination/virtual scroll, ng-model-options debounce, avoiding deep watches and heavy functions in templates, and disabling debug info in production.

Controllers Basic

A controller is a constructor function that AngularJS instantiates (with DI) for a piece of the view. Its job: set up initial state and expose functions the view can call. It should not manipulate the DOM, format data (use filters) or contain business logic and HTTP code (use services).

angular.module('shop').controller('ProductListCtrl', ProductListCtrl);

ProductListCtrl.$inject = ['ProductService'];          // explicit annotation, minification-safe
function ProductListCtrl(ProductService) {
  var vm = this;                                       // view-model
  vm.products = [];
  vm.loading = true;
  vm.remove = remove;

  activate();

  function activate() {
    ProductService.getAll().then(function (list) { vm.products = list; })
      .finally(function () { vm.loading = false; });
  }
  function remove(p) { return ProductService.remove(p.id).then(activate); }
}
<div ng-controller="ProductListCtrl as vm">
  <p ng-if="vm.loading">Loading...</p>
  <ul><li ng-repeat="p in vm.products track by p.id">{{ p.name }} <button ng-click="vm.remove(p)">x</button></li></ul>
</div>
angular.module('shop').controller('ProductListCtrl', ['$scope', 'ProductService',
  function ($scope, ProductService) {
    $scope.products = [];
    ProductService.getAll().then(function (list) { $scope.products = list; });
    $scope.remove = function (p) { /* ... */ };
  }]);
Why prefer controllerAs?No dependence on scope inheritance quirks (the dot rule), clearer templates (vm.x shows where data comes from), controllers become plain classes, and it is the natural stepping stone to .component() and to Angular 2+.

Rules of thumb

  • One controller per view / component; keep it thin and delegate to services.
  • Never inject $element/DOM into a controller; use directives for DOM work.
  • Do not share state between controllers via $rootScope; use a service.
  • Clean up in $scope.$on('$destroy', ...) (timers, listeners, intervals).

Why "track by" in ng-repeat?

By default ng-repeat tracks items by identity ($$hashKey added to objects). If you replace the list with fresh objects from the server (same data, new objects), every DOM node is destroyed and re-created. track by item.id lets AngularJS reuse the DOM for items whose id has not changed, which is faster and keeps focus and scroll position. It also avoids the ngRepeat:dupes error when a list contains duplicate primitives (track by $index).

Custom filter

angular.module('shop').filter('fileSize', function () {
  var units = ['B', 'KB', 'MB', 'GB'];
  return function (bytes, digits) {                 // the factory returns the filter function
    if (isNaN(bytes)) return '-';
    var i = 0;
    while (bytes >= 1024 && i < units.length - 1) { bytes /= 1024; i++; }
    return bytes.toFixed(digits === undefined ? 1 : digits) + ' ' + units[i];
  };
});
// {{ file.size | fileSize:2 }}
PerformanceFilters in templates re-run on every digest. Keep them cheap and pure (same input → same output; AngularJS skips re-running pure filters when inputs are unchanged). For heavy filtering of big lists, filter once in the controller ($filter('filter')(list, q)) when the query changes.

Part 2 — Dependency injection, services and HTTP

Dependency injection and minification Mid

Dependency injection (DI) means a component declares what it needs and the framework's injector supplies it. In AngularJS the injector looks at the names you ask for ($http, ProductService...) and passes the matching singleton instances.

Why DI?Components never create their own collaborators, so tests can replace $http with a mock and swap real storage for a fake. It also gives one place to configure shared objects (providers) and a lazily-created, app-wide singleton for each service.

Three ways to annotate dependencies

// 1. Implicit (by parameter name) - BREAKS when minified because $http becomes "a"
app.controller('A', function ($scope, $http) { });

// 2. Inline array annotation - safe
app.controller('B', ['$scope', '$http', function ($scope, $http) { }]);

// 3. $inject property - safe, readable, tool-friendly
function C($scope, $http) { }
C.$inject = ['$scope', '$http'];
app.controller('C', C);

// Automate it in the build: ng-annotate / babel-plugin-angularjs-annotate / ngAnnotate
// Or enforce the discipline at run time with ng-strict-di
"Unknown provider: aProvider <- a"This is the classic symptom of implicit injection after minification. Fix with array annotation/$inject, an annotate plugin in the build, or ng-strict-di to find them early in development.

factory vs service vs provider – the interview answer

service and factory are both shortcuts for provider. A provider is the full recipe: an object with a $get method that returns the service instance, and it is the only one configurable in the config phase. factory(fn) is a provider whose $get is fn. service(Ctor) is a factory that does $injector.instantiate(Ctor) (i.e. new). All produce singletons.

$http, promises ($q) and interceptors Mid

$http is the core service for XMLHttpRequest/JSON calls. It returns a promise (AngularJS's $q), and its callbacks run inside a digest, so the view updates automatically.

$http.get('/api/products', { params: { page: 2, q: 'phone' } })     // /api/products?page=2&q=phone
  .then(function (response) {
    // response.data, .status, .headers(), .config
    vm.items = response.data;
  })
  .catch(function (err) { vm.error = err.status + ' ' + err.statusText; })
  .finally(function () { vm.loading = false; });

$http.post('/api/orders', order, { headers: { 'X-Request-Id': id }, timeout: 5000 });

// Parallel calls
$q.all({ user: UserSvc.me(), orders: OrderSvc.mine() }).then(function (r) { vm.user = r.user; vm.orders = r.orders; });

// Create your own promise
function wait(ms) { var d = $q.defer(); $timeout(d.resolve, ms); return d.promise; }
.success() / .error() are removedThey were deprecated in 1.4 and removed in 1.6. Use .then() / .catch(). Note that .then gets the full response object, not only the data. Also from 1.6, an unhandled rejection logs "Possibly unhandled rejection" – always add a .catch.

Interceptors: cross-cutting HTTP concerns

An interceptor is a factory returning request, requestError, response and responseError hooks. They run for every $http call: ideal for auth headers, global error handling and loading spinners.

angular.module('shop').factory('AuthInterceptor', function ($q, $injector, TokenStore) {
  return {
    request: function (config) {
      var t = TokenStore.get();
      if (t) config.headers.Authorization = 'Bearer ' + t;
      return config;
    },
    responseError: function (rejection) {
      if (rejection.status === 401) $injector.get('$state').go('login');   // $injector avoids circular dependency
      return $q.reject(rejection);                                          // keep the chain rejected!
    }
  };
}).config(function ($httpProvider) {
  $httpProvider.interceptors.push('AuthInterceptor');
});
Promise essentials: chaining, error recovery, $q.when
  • .then(success, error) returns a new promise; returning a value resolves it, returning another promise waits for it, throwing or returning $q.reject() rejects it.
  • A .catch() that returns a normal value recovers the chain (later .then runs).
  • $q.all([...]) waits for all (fails fast); $q.race for the first; $q.when(x) wraps a value or third-party promise so it joins a digest.
  • Native Promise / async-await work, but their callbacks run outside the digest, so the view will not refresh unless you call $scope.$applyAsync(). Prefer $q (or wrap with $q.when) in AngularJS code.

A safe, AngularJS-friendly wrapper service

Wrap storage in a service: handles JSON, missing storage (private mode, quota exceeded), key prefixes, and makes tests easy to mock. Remember to trigger a digest if you update scope from the storage event.

angular.module('shop').factory('Store', function ($window, $rootScope) {
  var PREFIX = 'shop.';
  var backend = tryStorage($window.localStorage);
  function tryStorage(s) { try { s.setItem('__t', '1'); s.removeItem('__t'); return s; } catch (e) { return memory(); } }
  function memory() { var m = {}; return { getItem: function (k) { return k in m ? m[k] : null; }, setItem: function (k, v) { m[k] = String(v); }, removeItem: function (k) { delete m[k]; } }; }

  $window.addEventListener('storage', function (e) {            // sync across tabs
    if (e.key && e.key.indexOf(PREFIX) === 0) $rootScope.$applyAsync(function () { $rootScope.$broadcast('store:changed', e.key.slice(PREFIX.length)); });
  });

  return {
    get: function (key, fallback) {
      var raw = backend.getItem(PREFIX + key);
      if (raw === null) return fallback;
      try { return JSON.parse(raw); } catch (e) { return fallback; }
    },
    set: function (key, value) {
      try { backend.setItem(PREFIX + key, JSON.stringify(value)); return true; }
      catch (e) { return false; }                               // QuotaExceededError
    },
    remove: function (key) { backend.removeItem(PREFIX + key); }
  };
});

  • angular-cookies (ngCookies) – official cookie service (next chapter).

Part 8 — Interview preparation & revision

Self-test quiz Practice

Ten questions that interviewers like. Pick an answer, read the explanation, and keep score.

Common AngularJS interview questions Prep

Filter by topic, expand a question and try to answer it aloud first.

What is AngularJS and what problems does it solve? core

A client-side MVC/MVVM framework for SPAs. It adds declarative templates, two-way data binding, dependency injection, directives, routing support and testability, removing the manual DOM manipulation and plumbing of jQuery-style apps.

Explain the digest cycle and dirty checking. core

Each binding adds a watcher. After events AngularJS knows about ($http, ng-click, $timeout) it runs $rootScope.$digest(): loop through all watchers, compare current vs last value, call listeners for changes, and repeat while anything changed (max 10 iterations, else infdig). Cost is proportional to the number of watchers.

$apply vs $digest vs $timeout? core

$apply(fn) runs fn then digests from $rootScope; $digest() only from the given scope down; $timeout wraps setTimeout and applies automatically, and is also the safe way to defer to "after the current digest" without the inprog error.

What is scope inheritance and the "dot rule"? core

Child scopes prototypally inherit from their parent. Reading falls through to the parent; assigning a primitive shadows it on the child. Bind to object properties (ng-model="form.name") or use controllerAs so that writes mutate the shared object.

ng-if vs ng-show; ng-repeat track by? core

ng-if adds/removes DOM and creates a child scope; ng-show only toggles display and keeps watchers alive. track by item.id lets ng-repeat reuse DOM nodes for objects with the same key and avoids duplicate-key errors on primitives (track by $index).

What are isolate scope binding types @, =, <, &? core

@ one-way string (interpolated), = two-way, < one-way expression (preferred, 1.5+), & callback to the parent. Components use the same syntax in bindings.

Directive vs component; compile vs link? core

A component is a directive preset (element-only, isolate scope, controllerAs $ctrl, lifecycle hooks) for UI pieces. In directives, compile runs once per template and may transform the DOM; link (post-link) runs per instance to attach watchers and handlers.

What are filters and how do they affect performance? core

Functions that format/select data in templates or code ($filter). They run on every digest when used in expressions, so keep them pure and cheap, and for expensive transformations precompute in the controller.

What are promises in AngularJS? How does $q differ from native Promise? core

$q is a promise implementation integrated with the digest: resolution callbacks execute inside a digest so views update. Native promise callbacks run outside, requiring $apply. Use $q.all, $q.when, $q.defer, and always add .catch.

What is dependency injection and how does AngularJS implement it? di

Components declare dependencies by name and the injector (per app) creates/provides singletons from registered recipes. Names are read from parameter names, array annotation or $inject. Benefits: loose coupling, testability, configuration via providers.

service vs factory vs provider vs value vs constant? di

Provider is the base recipe with $get, configurable in config. Factory = function returning the service. Service = constructor instantiated with new. Value = simple injectable. Constant = available in config and cannot be decorated. All singletons.

config vs run block? di

config runs first, only providers/constants injectable, used for routes/interceptors. run runs after the injector is built, instances injectable, like main (auth listeners, initial data).

How do HTTP interceptors work and why return $q.reject? di

Interceptors are factories with request/requestError/response/responseError hooks pushed to $httpProvider.interceptors. In responseError you must return $q.reject(rejection), otherwise the chain is treated as recovered and callers would run their success path with an undefined value.

How do controllers talk to each other? di

Best: through a shared service or component bindings (inputs/callbacks). Alternatives: $emit/$broadcast/$on (implicit, easy to leak), require in directives, $rootScope (avoid).

ngRoute vs ui-router? route

ngRoute maps URL to a single view with ng-view, no nesting. ui-router models named, hierarchical states with nested/multiple ui-views, state-based navigation (ui-sref), inherited resolves, abstract layouts and transition hooks, and is preferred for real apps.

How do you pass and read route parameters? route

ngRoute: /products/:id read from $routeParams.id; query via $location.search(). ui-router: url: '/:id' and ?q declared on the state, read with $stateParams / $transition$.params() or injected into components via resolve bindings.

How do you protect routes (authentication/authorisation)? route

ngRoute: a resolve that rejects, or $routeChangeStart listener. ui-router 1.x: $transitions.onBefore hook redirecting to login, with data.requiresRole metadata. Always enforce on the server too: client guards are cosmetic.

Hashbang vs HTML5 mode; what changes on the server? route

Hashbang URLs keep the route after #! so the server never sees it. HTML5 mode uses the History API and clean URLs; it requires <base href> and server fallback to index.html for all non-file, non-API URLs (IIS rewrite, nginx try_files, ASP.NET Core MapFallbackToFile).

What is lazy loading of states/modules in AngularJS? route

AngularJS has no built-in module lazy loading. Use ui-router lazyLoad with ocLazyLoad or dynamic import() in a Webpack build to fetch a feature's chunk when its state is first entered and register its module at run time.

localStorage vs sessionStorage vs cookies? store

localStorage: persistent, ~5 MB, not sent to the server. sessionStorage: per tab, cleared when the tab closes. Cookies: ~4 KB, sent with every request, can be HttpOnly/Secure/SameSite, set expiry. Web Storage is synchronous and strings-only; both web storages are accessible to any script (XSS risk).

How would you store large or structured offline data? store

IndexedDB (via localForage/Dexie), optionally with a service worker and Cache API for the app shell. Wrap in a service returning $q promises, version the schema, and plan a sync strategy with the server.

Where do you store a JWT in an AngularJS SPA, and why? store

Prefer a short-lived access token in memory plus a refresh token in an HttpOnly, Secure, SameSite cookie. localStorage is simple but exposes tokens to XSS. Add CSP, sanitise HTML, clear on logout, and handle refresh with a single in-flight request.

What is $cacheFactory / $templateCache and the cache option of $http? store

In-memory caches. $http with cache: true stores GET responses for the page lifetime; $templateCache holds HTML templates (often prefilled by the build); $cacheFactory creates custom caches with optional capacity (LRU).

How do you keep state across a page refresh in a multi-step form? store

Keep the in-progress model in a service, and persist drafts in sessionStorage (per tab) or localStorage (per browser), or on the server for authenticated users. Restore in a resolve or $onInit; clear on completion. Never persist secrets.

Why do AngularJS apps break after minification and how do you prevent it? build

Implicit DI relies on parameter names. Minifiers shorten them. Use array/$inject annotation, run ng-annotate (babel-plugin-angularjs-annotate) in the pipeline, and enable ng-strict-di in development.

Gulp vs Webpack for AngularJS? build

Gulp is a task runner that pipes files through plugins (you manage order, concat, annotate, uglify, template cache). Webpack is a module bundler that builds a graph from imports, supports loaders (Babel, HTML, Sass), code splitting, hashed filenames and a dev server. Webpack suits modern/modular code; Gulp suits legacy script-tag projects.

What does the template cache step do? build

It converts HTML templates referenced by templateUrl into JavaScript that fills $templateCache (gulp-angular-templatecache) or inlines them with html-loader, avoiding one HTTP request per template at runtime.

How do you unit test a service that calls $http? build

Load the module with angular.mock.module, inject the service and $httpBackend, set expectGET(...).respond(...), call the service, then $httpBackend.flush() and assert. Verify no outstanding requests in afterEach.

How do you improve AngularJS performance? build

Reduce watchers (one-time bindings, ng-if, pagination), use track by, debounce ng-model, avoid deep watches and expensive template functions, disable debug info in production, bundle/minify/gzip, and lazy load features.

AngularJS is end of life. What would you do with a large legacy app? design

Reduce risk first (CSP, dependency audit, update to 1.8.3 or a supported fork), standardise on components and controllerAs, move builds to Webpack and TypeScript, add tests, then migrate incrementally to Angular (or another framework) with ngUpgrade/micro-frontends, converting leaf components and services first.

How would you structure a large AngularJS application? design

Feature-based folders each with its own module, routes, components and services; a thin core module for singletons (interceptors, auth, store); shared module for presentational components; container components talk to services, leaf components get data via < and emit via &; lazy-load big areas; keep state in services, not $rootScope.

How do you integrate an AngularJS front end with an ASP.NET Core Web API? design

Serve the built bundle as static files (or from a CDN), use HTML5 mode with MapFallbackToFile("index.html"), call the API with $http services plus an auth interceptor, enable CORS only when hosts differ, send the antiforgery token via X-XSRF-TOKEN for cookie auth, and generate typed API docs with Swagger/OpenAPI.
