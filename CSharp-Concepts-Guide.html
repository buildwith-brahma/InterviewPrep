Part 1 — Language fundamentals

C#, the CLR and .NET: the big picture Basic

C# is a statically typed, object-oriented, multi-paradigm language (it also supports functional and generic programming). .NET is the platform that compiles, runs and supplies the libraries for it. Understanding the layers explains most "why does it behave like this?" questions.

Why does it matter?C# source is not machine code. It is compiled to a portable Intermediate Language (IL) and then JIT-compiled to native code at run time. That is why the same assembly runs on Windows, Linux and macOS, why reflection is possible (metadata ships with the IL), and why startup and memory behave the way they do.

Types: value types vs reference types Basic

Every C# type is either a value type (stores the data itself) or a reference type (stores a reference to an object on the managed heap). This single distinction explains copying, equality, null, performance and many bugs.

Value types

int, long, double, decimal, bool, char, enum, struct (incl. DateTime, Guid, ValueTuple).

  • Assignment copies the data.
  • Cannot be null (unless Nullable<T>).
  • Stored inline: in a local variable on the stack, or inside the object that contains them on the heap.
  • Cheap for small, short-lived data.

Reference types

class, interface, delegate, record (class), string, object, arrays, dynamic.

  • Assignment copies the reference; both variables point to one object.
  • Can be null.
  • Object lives on the heap and is reclaimed by the garbage collector.
  • Identity matters (ReferenceEquals).

Boxing and unboxing

Boxing wraps a value type in an object on the heap; unboxing extracts it again with a cast. It allocates, so it is a hidden performance cost – mostly avoided by generics.

int i = 42;
object o = i;          // BOXING: heap allocation, value copied into the box
int j = (int)o;        // UNBOXING: type check + copy back
// long k = (long)o;   // InvalidCastException! The box holds an int, not a long

var list = new System.Collections.ArrayList();   // old, non-generic
list.Add(1);                                     // boxes every int
var good = new List<int>();                       // generic: no boxing
good.Add(1);

struct vs class: how to choose

Choose a struct only when all are true: it represents a single logical value (like a coordinate), is small (about 16 bytes or less), is immutable, and is short-lived. Otherwise use a class.

  • Structs are copied on every assignment and method call – large structs are slower, not faster.
  • Mutable structs are a classic bug source: you mutate a copy.
  • Use readonly struct / record struct to get immutability and value equality.
  • A struct inside a class lives inline in that object; a struct in an object variable is boxed.
public readonly record struct Money(decimal Amount, string Currency)
{
    public Money Add(Money other) => Currency == other.Currency
        ? this with { Amount = Amount + other.Amount }
        : throw new InvalidOperationException("Currency mismatch");
}

Strings and text Basic

string is a reference type that behaves like a value: it is immutable. Every "modification" creates a new string. It is a sequence of UTF-16 chars.

Why immutable?Safety (a string used as a dictionary key or in a security check cannot change underneath you), thread-safety without locks, and string interning (identical literals share one object). The price: repeated concatenation in a loop allocates many strings.
string a = "hello";
string b = "hel" + "lo";                        // compile-time constant: same literal
Console.WriteLine(ReferenceEquals(a, b));        // True (interned)
Console.WriteLine(a == b);                       // True: == on string compares CONTENT (operator overloaded)

// Building strings in a loop

Null handling and nullable types Basic

The billion-dollar mistakeTony Hoare called null references his "billion-dollar mistake": any reference can secretly be null and NullReferenceException appears at run time. C# gives two separate tools: nullable value types and nullable reference types.

1. Nullable value types: int?

int? is Nullable<int>, a struct holding a value plus a HasValue flag.

2. Nullable reference types (C# 8+, <Nullable>enable</Nullable>)

A compile-time annotation system. string means "should never be null"; string? means "may be null". The compiler warns when you dereference a maybe-null value. Nothing changes at run time – it is static flow analysis.

int? age = null;
Console.WriteLine(age.HasValue);            // False
int a = age ?? 18;                          // default when null
int b = age.GetValueOrDefault(18);

string? name = GetNameOrNull();
Console.WriteLine(name?.Length);            // null-conditional: null if name is null
Console.WriteLine(name?.Length ?? 0);       // combine with ??
int len = name!.Length;                     // '!' null-forgiving: "trust me" (no check - can still crash)

ArgumentNullException.ThrowIfNull(name);    // guard clause (C# 11 / .NET 6+)

if (name is not null) Console.WriteLine(name.Length);   // flow analysis now knows it's non-null

public class Person
{
    public required string Name { get; init; }   // C# 11: must be set by the initializer
    public string? Nickname { get; set; }        // explicitly optional
}
Rule of thumbTurn on nullable reference types in every project, treat warnings as errors in new code, validate at the boundary (public methods, controllers) and keep the interior non-null.

Exception handling Mid

An exception is an object (derived from System.Exception) representing an error. When thrown, the CLR unwinds the stack looking for a matching catch; finally blocks run on the way.

try
{
    var text = await File.ReadAllTextAsync(path);
    var cfg = JsonSerializer.Deserialize<Config>(text) ?? throw new InvalidDataException("empty config");
}
catch (FileNotFoundException ex) when (ex.FileName?.EndsWith(".json") == true)   // exception FILTER: no unwinding if false
{
    logger.LogWarning(ex, "Config missing, using defaults");
}
catch (JsonException ex)
{
    throw new ConfigurationException("Config is not valid JSON", ex);   // wrap + keep InnerException
}
finally
{
    Cleanup();         // always runs (except process crash / Environment.FailFast)
}

// rethrow correctly
try { Work(); }
catch (Exception ex) { Log(ex); throw; }        // 'throw;' keeps the original stack trace
// catch (Exception ex) { throw ex; }           // BAD: resets stack trace

// custom exception
public class OrderNotFoundException : Exception
{
    public int OrderId { get; }
    public OrderNotFoundException(int id) : base($"Order {id} not found") => OrderId = id;
}

Do

  • Catch only what you can handle.
  • Use using/finally for cleanup.
  • Use TryXxx for expected failures.
  • Throw specific types with clear messages; keep InnerException.
  • Log once at the boundary.

Don't

  • catch (Exception) { } (swallowing).
  • Use exceptions for normal control flow (slow: throwing costs microseconds).
  • throw ex; (loses the stack).
  • Return error codes AND throw.
  • Catch OutOfMemoryException and carry on.
Exception hierarchy and async exceptions

Exception → SystemException (NullReferenceException, ArgumentException → ArgumentNullException/ArgumentOutOfRangeException, InvalidOperationException, IndexOutOfRangeException, InvalidCastException, DivideByZeroException) and ApplicationException (obsolete advice; derive from Exception).

In async methods, an exception is captured in the returned Task and rethrown when you await it. With Task.WhenAll, await rethrows only the first exception; inspect task.Exception.InnerExceptions to see all of them. An un-awaited faulted task can go unobserved – always await or handle it.

Part 2 — Object-oriented programming

Classes, objects and members Basic

A class is a blueprint that bundles state (fields/properties) and behaviour (methods). An object is an instance created with new. Object-oriented design exists to keep related data and rules together and hide internals behind a stable surface.

public class BankAccount
{
    // FIELD: private storage (convention: _camelCase)
    private decimal _balance;

    // static member: belongs to the TYPE, shared by all instances
    private static int _created;
    public static int Created => _created;

    // constant (compile-time) vs readonly (set once at run time)
    public const int MaxOwnerLength = 50;
    public readonly Guid Id = Guid.NewGuid();

    // PROPERTIES: field access with logic
    public string Owner { get; }                              // read-only auto-property (set in ctor only)
    public decimal Balance => _balance;                       // computed / expression-bodied
    public string? Note { get; set; }                         // auto-property
    public DateTime OpenedUtc { get; init; } = DateTime.UtcNow;   // init-only: set at construction only

    // CONSTRUCTORS
    public BankAccount(string owner, decimal opening = 0)
    {
        if (string.IsNullOrWhiteSpace(owner)) throw new ArgumentException("Owner required", nameof(owner));
        Owner = owner;
        _balance = opening;
        _created++;
    }
    static BankAccount() { /* static ctor: runs once, before first use */ }

    // METHODS
    public void Deposit(decimal amount)
    {
        if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
        _balance += amount;
    }
    public bool TryWithdraw(decimal amount)
    {
        if (amount <= 0 || amount > _balance) return false;
        _balance -= amount;
        return true;
    }

    public override string ToString() => $"{Owner}: {_balance:C}";
}

The four pillars: encapsulation, inheritance, polymorphism, abstraction Basic

Encapsulation

Hide internal state; expose a small, safe API. The class guards its own invariants (e.g. balance never negative).

Abstraction

Expose what something does, hide how. Done with abstract classes and interfaces.

Inheritance

A derived class reuses and extends a base class (is-a relationship). Single class inheritance, multiple interface implementation.

Polymorphism

One interface, many behaviours: calling the same method on a base-type reference executes the derived implementation.

public abstract class Shape                         // abstract: cannot be instantiated; may have abstract members
{
    public string Name { get; }
    protected Shape(string name) => Name = name;
    public abstract double Area();                  // MUST be overridden
    public virtual string Describe() => $"{Name} with area {Area():F2}";   // MAY be overridden
}

public class Circle(double radius) : Shape("Circle")
{
    public override double Area() => Math.PI * radius * radius;
}
public class Rect(double w, double h) : Shape("Rectangle")
{
    public override double Area() => w * h;
    public override string Describe() => base.Describe() + $" ({w}x{h})";   // extend base behaviour
}

Every object has a hidden header pointing to its type's method table. A call to a virtual method looks up the slot in the table of the actual runtime type (late binding). Non-virtual calls are resolved at compile time (fast, inlinable).

How the runtime implements generics (reified generics)

Unlike Java's type erasure, .NET keeps generic type information at run time (reification). How Dictionary works (and why the hash contract matters)

A dictionary has an array of buckets. For a key it computes GetHashCode(), maps it to a bucket index (hash % buckets.Length), then walks a short chain comparing keys with Equals. When the load gets too high it resizes (roughly doubling to the next prime) and re-inserts everything. Cost is O(1) on average, O(n) if many keys share a hash. That is why mutable keys or a bad GetHashCode silently break lookups.

Deferred vs immediate execution

Most LINQ operators (Where, Select, OrderBy, GroupBy, Take...) are lazy: they just build a pipeline. Nothing runs until you enumerate (foreach) or call an operator that returns a concrete result (ToList, ToArray, ToDictionary, Count, First, Sum, Any).

Classic traps
  • Multiple enumeration: enumerating the same lazy query twice runs it twice (and may hit the database twice). Materialise with ToList() when reusing.
  • Captured variables: the query uses the variable's value at enumeration time, not definition time.
  • IEnumerable vs IQueryable: calling .AsEnumerable() / .ToList() too early pulls the whole table into memory and filters in C#. Keep filters on IQueryable so SQL does the work.
  • Count() vs Any(): use Any() to test for existence; Count() > 0 may enumerate everything.
  • Order of operators: filter (Where) before sorting/projecting to reduce the work.
How IEnumerable vs IQueryable differ internally

IEnumerable<T> operators take delegates (Func<T,bool>) and run in your process. IQueryable<T> operators take expression trees (Expression<Func<T,bool>>): a data structure describing the lambda. A provider (EF Core) walks the tree and translates it into SQL. A lambda that calls a C# method the provider cannot translate throws (or, in old EF, silently evaluated client-side).

Iterators, yield and IEnumerable Adv

{
    int a = 0, b = 1;
    while (true)                       // infinite sequence is fine: values are produced lazily
    {
        yield return a;                // pause here, hand a value to the caller
        (a, b) = (b, a + b);
    }
}

async / await and Tasks Mid

Asynchronous programming lets a method wait for slow work (disk, network, database) without blocking a thread. async/await lets you write that code in a straight-line style while the compiler builds a state machine behind the scenes.

Why does it exist?A thread costs about 1 MB of stack and scheduling time. If every waiting request holds a thread, a server runs out of threads long before it runs out of CPU. With await, the thread returns to the pool during the wait and any free thread resumes the method afterwards. Async is about scalability, not about making a single call faster.
public async Task<string> GetTitleAsync(string url, CancellationToken ct = default)
{
    using var http = new HttpClient();
    string html = await http.GetStringAsync(url, ct);        // thread is released here
    // ... continuation resumes here when the response arrives (maybe on a different thread)
    var m = Regex.Match(html, "<title>(.*?)</title>");
    return m.Success ? m.Groups[1].Value : "(none)";
}

Memory: stack, heap and the garbage collector Adv

.NET manages memory automatically. Understanding how explains performance problems (allocation pressure, GC pauses) and leaks.

The stack

  • Per-thread, LIFO, very fast (move a pointer).
  • Holds locals, parameters, return addresses, and value-type data declared locally.
  • Memory freed automatically when the method returns.
  • Limited size (about 1 MB): deep recursion → StackOverflowException (cannot be caught).

The managed heap

  • Shared; holds reference-type objects (and boxed values, closures, arrays).
  • Allocation is cheap (bump a pointer); cleanup is done by the GC.
  • Divided into generations 0, 1, 2 and the Large Object Heap (LOH, objects ≥ 85,000 bytes).

How the garbage collector works

  1. Mark: starting from roots (static fields, locals on stacks, CPU registers, GC handles) trace every reachable object.
  2. Sweep/Compact: reclaim the space of unreachable objects and (usually) slide survivors together to avoid fragmentation.
  3. Generational: new objects go to Gen 0. Survivors are promoted to Gen 1, then Gen 2. Most objects die young, so frequent cheap Gen 0 collections reclaim most memory. Gen 2 (full) collections are rare and expensive.

public class ResourceHolder : IDisposable
{
    private IntPtr _handle = Native.Open();              // unmanaged resource
    private readonly Stream _stream = File.OpenRead("x"); // managed disposable field
    private bool _disposed;

    public void Dispose() { Dispose(true); GC.SuppressFinalize(this); }   // dispose pattern
    protected virtual void Dispose(bool disposing)
    {
        if (_disposed) return;
        if (disposing) _stream.Dispose();     // only touch other managed objects when called explicitly
        Native.Close(_handle);                // always free unmanaged resources
        _disposed = true;
    }
    ~ResourceHolder() => Dispose(false);      // only needed when directly owning an unmanaged handle
}
Memory leaks in a garbage-collected language

A leak means an object is still reachable though no longer needed. Typical causes:

  • Events not unsubscribed (publisher holds subscriber).
  • Static collections/caches that only grow (use MemoryCache with size limits/expiry).
  • Captured variables in long-lived lambdas.
  • Not disposing IDisposables (handles, HttpClient misuse, timers).
  • Thread-static/closures keeping large graphs alive.

Tools: dotnet-counters, dotnet-gcdump, dotnet-dump, Visual Studio memory profiler, PerfView. WeakReference lets you reference an object without keeping it alive.

    public double Y { get; } = y;

    public static bool operator !=(Vector2 a, Vector2 b) => !a.Equals(b);

    public bool Equals(Vector2 o) => X == o.X && Y == o.Y;
    public override bool Equals(object? o) => o is Vector2 v && Equals(v);
    public override int GetHashCode() => HashCode.Combine(X, Y);

    public static implicit operator Vector2((double, double) t) => new(t.Item1, t.Item2);
    public static explicit operator double(Vector2 v) => Math.Sqrt(v.X * v.X + v.Y * v.Y);
}

Common C# interview questions Prep

Filter by topic, expand a question and try to answer it aloud first.

What is the difference between value types and reference types? core

Value types (struct, enum, primitives) hold their data directly and are copied on assignment; reference types (class, string, arrays, delegates) hold a reference to a heap object, so assignment copies the reference. Value types cannot be null (without Nullable<T>). Value locals live on the stack; value fields live inside their containing object.

What is boxing and why is it expensive? core

Converting a value type to object/interface allocates a heap object and copies the value into it; unboxing type-checks and copies back. It causes allocations and GC pressure. Avoid with generics (List<int>) and by not passing value types to object parameters in hot paths.

string vs StringBuilder? core

string is immutable, so each concatenation allocates a new string (O(n²) in a loop). StringBuilder appends into a growable buffer and creates the string once. Use the builder for many appends; use interpolation or + for a few.

const vs readonly vs static readonly? core

const is a compile-time literal baked into callers (changing it requires recompiling dependants). readonly fields are assigned at declaration or in the constructor and can be any type. static readonly is a run-time constant shared by the type, initialised in the static constructor.

ref vs out vs in? core

ref: pass by reference, must be initialised, can be read/written. out: callee must assign, caller need not initialise. in: pass by read-only reference to avoid copying large structs.

What are nullable reference types? Do they prevent NullReferenceException at run time? core

A compile-time annotation/flow analysis feature (string vs string?) that warns about possible null dereferences. It does not change run-time behaviour, so nulls can still sneak in from unannotated libraries, reflection, JSON deserialisation or the null-forgiving operator !.

What is the difference between == and Equals()? core

For reference types == compares references unless the operator is overloaded (string overloads it to compare content); Equals is a virtual method that types override to define value equality. ReferenceEquals always checks identity.

What is the difference between is, as and a cast? core

is tests type (and with patterns binds a variable). as returns the converted reference or null (never throws; reference/nullable types only). A cast (T)x throws InvalidCastException on failure.

Abstract class vs interface – when do you use each? oop

Interface: a capability contract that unrelated types can implement; multiple per class; no instance state. Abstract class: a shared base with state, constructors and partial implementation for closely related types; single inheritance. Prefer interfaces for dependencies and testing; abstract classes for template-method style bases.

virtual vs override vs new? oop

virtual allows overriding. override replaces it and participates in polymorphism (dispatched on runtime type). new hides a member: the version called depends on the compile-time variable type, which is usually a bug source.

What is polymorphism? Compile-time vs run-time. oop

Run-time (subtype) polymorphism: a base reference invokes the derived override through virtual dispatch. Compile-time: method overloading, operator overloading and generics resolved by the compiler.

What is the difference between a class and a record? oop

Records are classes (or structs) with compiler-generated value equality, ToString, deconstruction and with copying, meant for immutable data. Classes use reference equality and suit entities with identity and behaviour.

Explain SOLID briefly. oop

Single responsibility; Open/closed (extend without editing); Liskov substitution (subtypes honour the base contract); Interface segregation (small focused interfaces); Dependency inversion (depend on abstractions, inject dependencies). They reduce coupling and make code testable.

Composition vs inheritance? oop

Inheritance models is-a and creates tight coupling to the base. Composition (has-a) assembles behaviour from collaborators, is easier to change and test. Favour composition; use inheritance for true substitutable hierarchies.

What does sealed do and why use it? oop

It prevents inheritance (or further overriding). It communicates design intent, protects invariants, and lets the JIT devirtualise/inline calls for a small speed gain.

Array vs List<T>? coll

Arrays are fixed-size contiguous blocks (fast, covariant). List<T> wraps an array and grows (doubling capacity) with amortised O(1) append; use arrays for fixed data and hot loops, lists otherwise.

How does a Dictionary work internally and when does it degrade? coll

Hashes the key to a bucket, then compares keys with Equals in the chain; resizes when it grows. Degrades towards O(n) with many hash collisions (poor GetHashCode) and breaks if a key's hash changes after insertion.

IEnumerable vs ICollection vs IList vs IReadOnlyList? coll

IEnumerable: forward iteration. ICollection: adds Count/Add/Remove/Contains. IList: adds index access. IReadOnlyList: Count + index without mutation. Accept the narrowest abstraction, return a read-only one.

First vs FirstOrDefault vs Single vs SingleOrDefault? coll

First throws if empty; FirstOrDefault returns default. Single throws if there are zero or more than one; SingleOrDefault throws on more than one but returns default on zero. Use Single when more than one is a bug you want detected.

What is deferred execution in LINQ? coll

Query operators build a pipeline and run only when enumerated, each time you enumerate. Operators like ToList, Count, First force execution. Beware multiple enumeration and queries observing later source changes.

Select vs SelectMany? coll

Select maps each element to one result. SelectMany maps each element to a sequence and flattens them into one (like flat-map): orders.SelectMany(o => o.Lines).

What is yield return? coll

It turns a method into a lazy iterator: the compiler generates a state machine that returns one element per MoveNext(), retaining local state between calls. Good for streaming large or infinite sequences with minimal memory.

How does async/await work? async

The compiler converts the method into a state machine. At an await on an incomplete task it registers the rest of the method as a continuation and returns to the caller, freeing the thread. When the awaited operation completes the continuation resumes (on the captured context or a pool thread). No thread is blocked while waiting for I/O.

Task vs Thread? async

A thread is an OS execution resource. A Task is an abstraction of a unit of work/promise, usually scheduled on pool threads, composable (WhenAll, continuations), able to return results and exceptions, and for I/O often using no thread at all.

What is ConfigureAwait(false)? async

It tells await not to resume on the captured SynchronizationContext. Libraries use it to avoid deadlocks and context switches. ASP.NET Core has no context, so it matters mainly for library code and UI apps.

Task.WhenAll vs sequential awaits; Task.WhenAny? async

Sequential awaits add durations; WhenAll starts all operations and completes after the slowest (time = max). WhenAny completes when the first finishes (timeouts, racing replicas). Only run tasks concurrently when they are independent.

lock vs Monitor vs SemaphoreSlim vs Interlocked? async

lock is sugar over Monitor for short critical sections (cannot await inside). SemaphoreSlim limits concurrency and supports WaitAsync. Interlocked performs lock-free atomic operations on single variables.

What is a race condition vs a deadlock? async

A race condition is when correctness depends on the timing of concurrent accesses to shared state (lost updates). A deadlock is when threads wait on each other forever (circular lock acquisition, or blocking on async code with a captured context). Fix with consistent lock order, immutability, atomic ops, or avoiding blocking.

ValueTask vs Task? async

ValueTask<T> avoids a heap allocation when the result is already available synchronously. It has restrictions (await once, do not store/await multiple times) so use it only on measured hot paths; default to Task.

How does the garbage collector work? mem

A generational, mark-and-compact collector. It marks objects reachable from roots, reclaims the rest and compacts survivors. Gen 0 holds new objects and is collected often; survivors are promoted to Gen 1 and Gen 2. Large objects (85 KB+) go to the LOH. Concurrent/background GC reduces pause times.

IDisposable vs finalizer; what is the dispose pattern? mem

Dispose releases resources deterministically (using). A finalizer is a non-deterministic safety net run by the GC and costs extra GC cycles. The pattern: public Dispose() calls Dispose(true) and GC.SuppressFinalize; the finalizer calls Dispose(false) and touches only unmanaged resources.

Stack vs heap? mem

Stack: per-thread LIFO for call frames and local value data; automatic cleanup, fast, small. Heap: shared memory for objects, collected by the GC. "Value types go on the stack" is an oversimplification: they live wherever their container lives (a field of a heap object is on the heap).

What causes memory leaks in .NET? mem

Unwanted references: event handlers never unsubscribed, static collections/caches that grow, long-lived closures, undisposed unmanaged resources, timers. Diagnose with a heap dump and find the GC roots retaining the objects.

What are Span<T> and why are they fast? mem

A stack-only view over contiguous memory with pointer + length. Slicing makes no copy or allocation, so parsing and buffer manipulation avoid GC pressure. Restrictions: cannot be stored in fields of classes, boxed, or used across await.

What is the difference between .NET Framework, .NET Core, .NET Standard and .NET 5+? mem

.NET Framework: Windows-only legacy. .NET Core: cross-platform rewrite. .NET Standard: an API specification for sharing libraries across them (superseded). .NET 5+ unified everything under one cross-platform platform ("just .NET"); target net8.0 or later for new work.

How do you design for testability in C#? design

Depend on interfaces, inject dependencies via constructors (DI), keep logic out of static/global state, separate pure logic from I/O, wrap time/randomness (TimeProvider), and write small focused classes so unit tests can substitute fakes.

Singleton in C# – how and should you? design

Thread-safe options: Lazy<T> or a static readonly field. In modern apps prefer registering the service with a singleton lifetime in the DI container; it is testable and avoids hidden global state.

How would you remove duplicates from a list while preserving order? design

list.Distinct() keeps the first occurrence in order (uses a hash set internally). For custom key: DistinctBy(x => x.Id) (.NET 6). Manually: iterate with a HashSet<T> and add to the result when seen.Add(item) returns true.

How do you detect a duplicate or find the first non-repeating character? design

Count with a dictionary in one pass, then scan in original order: s.GroupBy(c => c).Where(g => g.Count() == 1).Select(g => g.Key).FirstOrDefault() is clear; a Dictionary<char,int> plus second loop is O(n) with no LINQ overhead.
